Multi-Hypothesis Distillation (MHD) - Detailed Coding Pipeline
==============================================================

This document outlines the detailed, step-by-step pipeline required to implement and code the Multi-Hypothesis Distillation approach for low-resource machine translation.

--- PHASE 1: DATA PREPARATION ---

1. Data Acquisition
   - English Monolingual Data: Extract a raw subset from the OSCAR-3301 dataset.
   - Swahili Monolingual Data: Extract from the "Monolingual African Languages from ParaCrawls" collection (WMT22).
   - Validation/Test Data: Download the FLORES+ benchmark. Use the `dev` split for model validation/early stopping, and `devtest` for final evaluation.

2. Cleaning & Sampling
   - Filtering: Process the raw monolingual corpora using `monocleaner` with ready-to-use language packages.
   - Thresholding: Discard any sentences that score below 0.5.
   - Sampling: From the cleaned corpora, randomly sample three distinct working subsets to test data scaling: 100,000, 500,000, and 1,000,000 sentences.

--- PHASE 2: DISTILLATION (THE MHD CORE) ---

3. Teacher Generation
   - Model: Load the pre-trained `NLLB-200 1.3B` model (or the 3.3B variant).
   - Iteration: Run the teacher model over the monolingual source text to generate M hypotheses per sentence (M in {1, 3, 5, 10}).
   - Decoding Configurations to Implement:
     * Beam Search (BS): `beam_width = 10`. Keep the top M paths.
     * Diverse Beam Search (DBS): `beam_width = 10`, `groups = 10`, diversity penalty lambda = 0.5.
     * Top-k Sampling: k = 10. Sample M times.
     * Top-p (Nucleus) Sampling: p = 0.7. Sample M times.
     * Minimum Bayes' Risk (MBR): Generate 256 candidates using epsilon sampling (epsilon = 0.02). Calculate utility distance using `fastChrF` and select the M hypotheses with the highest expected utility.

4. MHD Corpus Construction
   - Flattening: Restructure the outputs into standard parallel corpora datasets (D_Z^M).
   - Mapping: For each source sentence x_i, duplicate it M times so that it pairs 1:1 with each generated hypothesis (y_i,1 to y_i,M).
   - Example: 100k sentences with M=10 results in a 1 million sentence-pair training corpus.

--- PHASE 3: STUDENT TRAINING ---

5. Tokenization
   - Algorithm: Train a new `SentencePiece` model.
   - Type: Joint bilingual Byte-Pair Encoding (BPE) model. Train a distinct tokenizer for each language pair and corpus variant.
   - Vocabulary: Restrict the vocabulary size to exactly 10,000 tokens.

6. Student Training (Fairseq)
   - Architecture: Standard base Transformer (~65M parameters).
     * Encoder/Decoder Layers: 6 each.
     * Embedding Dimension: 512.
     * FFN Dimension: 2048.
     * Attention Heads: 8.
   - Hyperparameters:
     * Optimizer: Adam (beta1=0.9, beta2=0.98).
     * Learning Rate: 0.0007.
     * Warm-up Updates: 8,000.
     * Batching: 8,000 max tokens per batch.
     * Dropout: 0.1.
     * Gradient Accumulation: Update weights after every 2 training steps.
     * Loss Function: Cross-entropy with label smoothing.
   - Checkpointing: Evaluate loss on the FLORES+ `dev` set after every epoch. Trigger early stopping after 6 validation steps with no improvement.

--- PHASE 4: EVALUATION & ANALYSIS ---

7. Evaluation
   - Inference: Translate the FLORES+ `devtest` set using the trained student model with standard Beam Search (`beam = 5`).
   - Primary Metric: Calculate `chrF++` (standardized for morphological complexity).
   - Secondary Metrics: Calculate `BLEU` and `COMET` (for supported pairs like eng-swh).
   - Significance: Run paired approximate randomization to validate statistical significance against standard sequence-level KD (D_BS^1).

8. Advanced Analysis
   - Variability: Run self-BLEU across the M hypotheses for each source sentence.
   - Lexical Richness: Plot Zipf distributions of the synthetic corpora vs. a native corpus.
   - Gender Bias: Use the WinoMT dataset to perform contrastive conditioning (evaluate if the student model assigns a higher probability to correctly gender-disambiguated cues).
   - Hallucination Detection: Extract sentence-level SONAR embeddings for model outputs and references. Calculate cosine similarity and compare against a baseline of completely shuffled references.
